# AI 사용 기록

AI는 개념 질문과 직접 작성한 코드의 오류 원인을 확인할 때 사용할 수 있습니다. 미작성 빈칸, 과제 전체, 평가 사례나 선택 심화의 설계를 대신 완성해 달라고 요청하지 않습니다. 실제 실행 결과를 만들거나 고쳐 달라고 요청하지 않습니다.

사용하지 않았다면 아래에 사용하지 않음이라고 적으세요. 사용했다면 필요한 만큼 기록하세요. API 키나 원문 개인정보를 대화에 넣지 않습니다.

사용 도구: Claude Opus 5.5

질문과 관련 함수: 
1. 과제에는 Dense 임베딩 유사도 검색만 있고 BM25 같은 키워드 검색이 없는데, 선택 심화에서 RRF를 어떻게 하는지 질문했다.
(`fuse_rankings`, `support.py`의 challenge 단계 키워드 순위 생성 코드)

2. 문서에 쓰인 정식 명칭과 사용자가 부르는 별칭이 다를 때 어떻게 검색하는지 과제 코드를 기준으로 질문했다. 
(`rewrite_query`, `search`, `answer_question`, `support.py`의 `evaluate`와 `live_generator`)


이해한 내용:
1. 키워드 검색은 main.py가 아니라 support.py의 challenge 단계에 들어 있다. "VPN", "승인", "요청"이 본문에 몇 개 들어 있는지 세어 정렬하는 단순한 방식이고 BM25는 아니다. RRF는 원래 점수가 아니라 각 목록의 순위만 써서 1/(60+순위)를 더하기 때문에, 척도가 다른 코사인 유사도와 단어 개수를 그대로 더하지 않고도 합칠 수 있다. 그래서 키워드 순위가 BM25에서 왔든 단어 개수에서 왔든 RRF 계산 방식은 같다.

2. 임베딩 모델은 "초록문"이 사내에서 VPN 원격 접속을 뜻한다는 것을 모르기 때문에 별칭으로 검색하면 맞는 문서와 벡터가 멀어질 수 있다. 그래서 rewrite_query로 aliases.json의 별칭을 정식 명칭으로 치환한 질문으로 검색한다. 답변 생성에는 사용자가 실제로 한 원래 질문을 넘기고, 시스템 프롬프트에 별칭 사전을 넣어 모델이 별칭과 정식 명칭을 연결하게 한다. evaluate는 문서와 top_k=1을 같게 두고 검색용 질문만 바꿔 비교하므로 Recall 차이를 질문 변환의 효과로 볼 수 있다. 다만 사전에 없는 별칭이나 띄어쓰기가 다른 표현은 처리하지 못하고, 단순 문자열 치환이라 다른 단어 안의 부분 문자열까지 바뀔 수 있다는 한계가 있다.
