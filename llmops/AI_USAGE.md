# AI 사용 기록

AI는 개념 설명과 직접 작성한 코드의 오류 원인 확인에 사용할 수 있습니다. 과제 전체, 미작성 TODO, 프롬프트 문장, 선택 심화 설계를 대신 완성하도록 요청하지 않습니다.

사용하지 않았다면 아래에 사용하지 않음이라고 적습니다. 사용했다면 필요한 만큼 항목을 추가하세요. API 키나 개인정보는 기록하지 않습니다.

- 사용 도구: Claude Opus 5.5
- 질문한 내용: 이메일과 전화번호를 [EMAIL], [PHONE]으로 바꾸는데, 패턴에 맞지 않아 변환되지 않으면 원문이 그대로 기록되는지 질문 (`mask_text`, `support.py`의 Langfuse `mask` 훅과 `masked` 검사)
- 이해한 내용: 그대로 기록된다. mask_text는 정규식 sub로 일치하는 부분만 바꾸고, 일치하지 않으면 오류나 경고 없이 원문을 돌려준다. PHONE 패턴은 01X-XXX(X)-XXXX처럼 하이픈이 있는 휴대폰 번호만 잡는다. 마스킹은 모델 입력(질문, 문서), Langfuse 관측 기록, 모델 출력과 최종 답변에 적용되므로, 패턴을 벗어난 개인정보는 이 모든 곳에 원문으로 남는다. support.py의 masked 검사도 같은 정규식을 한 번 더 적용해 비교하는 방식이라 패턴 밖의 형식은 잡지 못한다. 즉 이 검사는 "패턴에 맞는 연락처가 남지 않았다"는 것만 보장한다. 실무에서는 패턴 확장, 전용 개인정보 탐지 도구, 원문 수집 최소화 같은 방법으로 보완한다.
- 직접 수정한 부분: 없음 (개념 확인 질문)
- 다시 실행한 명령과 확인 결과: 직접 실행하지 않음. AI가 같은 정규식으로 확인한 결과, 하이픈 없는 번호(01012345678), 국제번호(+82-10-...), 유선 번호(02-123-4567)는 마스킹되지 않음

- 사용 도구: Claude Opus 5.5
- 질문한 내용: 과제는 must_include, must_not_include 같은 문구를 코드로 검사하는데, 실무에서는 답변을 사람이 평가하는 경우가 많은지 질문 (`cases.json`의 `expected`, `FEEDBACK`)
- 이해한 내용: 실무에서는 사람 평가만 쓰기보다 규칙 기반 자동 검사, LLM 심사, 사람 평가, 운영 중 사용자 피드백을 단계적으로 섞어 쓴다. 문구 검사는 빠르고 결과가 항상 같아 회귀 테스트에 좋지만, 같은 뜻을 다르게 쓴 맞는 답을 불합격시키거나, 필수 문구만 들어간 틀린 답을 통과시킬 수 있다. 그래서 정답 기준과 채점 기준 만들기, 자동 평가 결과 검증, 위험도가 높은 사례, 애매한 사례, 배포 전 최종 확인에는 사람이 들어간다. 과제의 FEEDBACK 작성과 실제 답변 8개 확인이 이 사람 평가 역할을 하며, status="ok"여도 passed=False일 수 있듯 오류 없이 답변이 나왔다고 정답은 아니다.
- 직접 수정한 부분: 없음 (개념 확인 질문)
- 다시 실행한 명령과 확인 결과: 없음
