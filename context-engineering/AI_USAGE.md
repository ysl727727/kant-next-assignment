# AI 사용 기록

AI는 개념 질문과 직접 작성한 코드의 오류 원인 확인에 사용할 수 있습니다. 과제 전체, 미작성 빈칸, 선택 심화의 설계나 정답을 대신 작성하도록 요청하지 않습니다. 설명을 이해한 뒤 직접 수정하고 다시 검사하세요.

사용하지 않았다면 아래에 사용하지 않음이라고 적습니다. 사용했다면 필요한 만큼 행을 추가하세요. API 키와 개인 정보는 기록하지 않습니다.

| 사용 도구 | 질문 | 이해한 내용 | 직접 수정한 부분 | 다시 실행한 명령과 결과 |
|---|---|---|---|---|
|Claude Opus 5.5| 대화가 얼마나 길어지면 예전 대화가 입력에서 빠지는지, 어떤 코드가 이를 결정하는지 질문 (`select_window`, `summarize`, `support.py`의 `compare`) | 정해진 턴 수가 아니라 토큰 예산으로 결정된다. 예산은 limit - RESERVE(384) - MARGIN(128)이고, 한도 2,300이면 1,788토큰이다. 예산에는 고정 지시, 참고 자료, 요약, 현재 질문이 모두 포함된다. select_window는 가장 최근 턴부터 거꾸로 하나씩 붙여 전체 입력 토큰을 세고, 예산을 넘는 순간 break해서 그보다 오래된 턴을 모두 뺀다. 턴 단위로 넣기 때문에 사용자와 어시스턴트 메시지는 함께 남거나 함께 빠진다. 빠진 턴의 사실은 summarize가 최신 값과 출처 턴으로 따로 보존하므로, "요약과 최근 대화" 방식에서는 담당자, 마감일, 승인조건이 유지된다. | 없음 (개념 확인 질문) | 없음 |
|Claude Opus 5.5| 같은 대화가 두 번 처리될 때 요약과 변경 이력이 중복 저장되는지 질문 (`merge_summary`, `checks.py`의 `replay` 검사) | 중복 저장되지 않는다. merge_summary는 processed_ids에 이미 있는 턴 ID를 continue로 건너뛰고, 처음 처리한 턴은 사실이 없어도 ID를 기록한다. 새 턴이어도 값이 같으면 changes에 추가하지 않고 current의 출처만 최신 턴으로 바꾼다. checks.py의 replay는 같은 턴을 다시 넣은 결과가 이전 결과와 완전히 같은지 검사한다. 같은 입력을 여러 번 처리해도 결과가 같은 성질을 멱등성이라고 하며, 재시도나 재실행이 잦은 실무에서 중요하다. | 없음 (개념 확인 질문) | 없음 |
